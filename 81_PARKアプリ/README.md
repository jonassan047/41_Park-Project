# PARK アプリ

PARK プロジェクトの仕組みを、そのまま動く Web アプリにしたもの（2026-10-15、試作 v0.1）。
企画書（[-19](../80_企画書/2026-10-14-19-ご提案.pptx)）と[システムの流れ](../30_検討/2026-10-14-04-システムの流れ.md)、[成約率を最優先にする](../30_検討/2026-10-14-02-成約率を最優先にする.md)のアイディア A〜K をもとに作った。

## 起動のしかた

- `start.bat` をダブルクリックする（ブラウザで http://localhost:4100/ が開く。止めるときは黒い画面を閉じる）。
- または、このフォルダで次を実行する。

```
node --no-warnings server.js
```

- Node.js 22.13 以上が要る（標準の SQLite を使うので、追加のインストールは不要。npm も使わない）。
- データは `data/park.db`。**Git には上げない**（エンジニアの個人情報が入る。このリポジトリは公開）。

## 見本データ（すべて架空）

いま入っているのは見本データ。パスワードはどれも `park1234`。

| 役割 | メールアドレス |
|---|---|
| 運営 | admin@park.example |
| SES | ses1@park.example（みどり情報システム）、ses2@、ses3@ |
| エンジニア | eg1@park.example（山田）、eg2@（佐藤）、eg3@（鈴木） |

本番のデータで始めるときは、`data` フォルダを消してから起動する。最初の画面で、運営のアカウントを作る。見本データを入れ直すときは、`data` を消してから次を実行する。

```
node --no-warnings scripts/seed.js
```

## できること

### 運営（tezzo）

- ダッシュボード：申し込み・やること（スキルシート提出・面談設定・成約）・募集中の案件・面談の予定・終わりが近い契約・未読メッセージ・今月の成功報酬
- SES：参加申込の承認（担当者に招待メール）、停止、担当者の追加、エンジニアの登録
- 案件：登録（**案件メールの本文を貼ると項目を自動で抜き出す**。PC の中で処理し、外部に送らない）、編集、状態（募集中・充足・終了）
- **マッチング**：案件票（必須・尚可・年数・単価・開始日・働き方）と経験票を突き合わせて点数を付け、合う点・足りない点を出す。選んだ人にメールで配信し、所属の SES にも知らせる
- 応募・選考：段階ごとのボード。スキルシート提出 → 書類通過 → 面談設定（**案件に合わせた面談対策の Q&A を自動で作る**。直せる）→ 結果 → 成約（契約を作る）。見送りは理由を選んで記録
- 契約：延長・終了・成約後のフォロー（調子と困りごと。悪いと運営に通知）
- 請求：月ごとに SES 別の請求書（初期費用・月額費用・消費税）を作り、発行・入金を記録。印刷・PDF
- やり取り：エンジニアとのスキルシートの相談（レビュー依頼）
- メール：送信箱（全部の中身を見られる）、一斉配信（SES・エンジニア・待機中の人）、送り直し
- 分析：応募 → 成約のファネル、SES ごとの成約率、見送りの理由、配信 → 応募率、延長率、応募から成約までの日数
- 設定：率（初期 7%・月額 3%。月額を何か月目からにするか）、消費税、配信の最低点、運営メンバーの招待、テストメール
- 操作の記録：配信・選考・請求などをすべて記録（公平性のため）。運営者本人がエンジニアとして入る場合の「運営者」の印

### SES

- ダッシュボード：所属エンジニア・選考中・成約率・今月の成功報酬の見込み・まだ応募していない配信・経験票がまだの人
- エンジニアの登録（ご本人に招待メール）と編集
- 案件：グループ全体の募集中の案件、自社が登録した案件。案件ごとに**自社のエンジニアとの相性**を見て、本人に案内・応募を出せる
- 応募・選考、契約、請求書、会社情報

### エンジニア

- 招待メールからパスワード設定（**個人情報の取り扱いに同意**）
- ホーム：届いた案件・面談の予定・スキルシートの完成度と直すところ・配属後のひとこと
- 届いた案件：相性・合う点・足りない点を見て、**条件（開始・金額・働き方）を確かめて応募**、または理由を選んで見送る
- プロフィール・スキル（年数・レベル）・経験票（案件ごとの技術・工程・成果）
- スキルシート：印刷・PDF。**案件に合わせて並べ替え**、名前をイニシャルで伏せる版
- 面談対策の Q&A と、自分用の練習メモ
- 運営とのやり取り

### 共通

- 通知（ベル）とメール。メールを受け取るかは各自で選べる
- パスワードの変更・再設定（メール）

## メールを実際に送るには

最初は「保存のみ」（送らずに、運営の「メール」画面で中身を確認できる）。送るときは、このフォルダに `config.local.json` を作る（Git には上げない）。

```
{
  "smtp": { "host": "smtp.gmail.com", "port": 465, "user": "送信に使うアドレス", "pass": "アプリ パスワード", "from": "送信に使うアドレス" }
}
```

- Gmail は「アプリ パスワード」が要る。ポートは 465（SSL）か 587（STARTTLS）。
- 設定したら、運営の「設定」→「テストメールを送る」で確かめる。
- 「設定」の「この画面の URL」を、実際に開く URL にする（メールのリンクに使う）。

## 動作確認

```
node --no-warnings test/smoke.js
```

一時フォルダに見本データを作り、3つの役割で主な画面と操作（申込・承認・取り込み・配信・応募・二重応募の拒否・見送り・請求・一斉配信・招待）をたどる。

## つくり

| ファイル | 中身 |
|---|---|
| `server.js` | 入口（ルーター・セッション・CSRF） |
| `src/db.js` | テーブルと設定の初期値 |
| `src/services.js` | 業務の手続き（招待・登録・配信・応募・選考・成約・延長） |
| `src/match.js` | マッチングの点数 |
| `src/qa.js` | 面談対策の Q&A、スキルシートの完成度 |
| `src/parse-case.js` | 案件メールの取り込み |
| `src/billing.js` | 成功報酬の計算 |
| `src/mail.js` | 送信箱・SMTP・通知・操作の記録 |
| `src/routes/` | 画面（public・cases・engineers・pipeline・admin・ses・eg） |

## まだやっていないこと（次の候補）

- インターネットに公開する（いまは自分の PC の中だけで動く。公開するなら、サーバー・HTTPS・バックアップが要る）
- 案件メールの自動受信（いまは本文を貼り付ける）
- AI による Q&A・スキルシートの下書き（個人情報・案件を外に出さない約束との兼ね合いを決めてから）
- 誓約書・利用規約の画面、ファイル（既存のスキルシートの Excel など）の添付
