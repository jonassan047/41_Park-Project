## 1. 背景・目的

### 1-1. 背景

- 商流：大手企業 → SH（一次受けのソフトハウス）→ SES（小さな協力会社。たくさんある）→ EG（エンジニア）。
- SES どうしは知り合いの間で仕事を回し合っているが、案件は個別に待つしかなく、人が足りずに取りこぼすこともある。
- EG は孤独になりやすく、技術・知識もたまりにくい。書類や面談の準備が追いつかず、落ちることも多い。
- TEZZO は SES の下の EG として15年以上働いてきた。その経験から、SES と EG の両方が良くなる仕組みを作りたい。

### 1-2. 目的

- **小さな SES の会社どうしを1つのグループ（GP）にまとめ、届いた案件に、グループ全体のエンジニアからいちばん合う人を出して、成約率を上げる。**
- いちばん大事なのは、エンジニアの成約率を上げること（2026-10-14 TEZZO）。
- 成約したときだけ、成功報酬をいただく（収益は 7 章）。

## 2. 範囲

### 2-1. やること

- 管理者・SES・担当者・EG の登録と管理（招待・仮登録・本登録・停止・退会）
- 案件の受け付け・仕分け・EG への割り振り
- 応募・面談・成約の記録
- スキルシートづくりと、面談対策の Q&A
- 結果をためて次に活かす（学習ループ）
- 請求（成功報酬）

### 2-2. やらないこと（今のところ）

- SH・大手企業がシステムを使うこと（SH には当面知られないように進める）
- 案件の内容・会社の名前を外部のサービスに渡すこと

## 3. 登場人物

| 登場人物 | 何をする人か |
|---|---|
| 管理者（運営） | PARK を運営する。SES・管理者を招待し、全体を見る。TEZZO が管理者 |
| SES（代表者） | 会社として GP に入り、所属する EG を登録する。成約したら費用を払う |
| 担当者 | SES の代表者以外の社員（2026-10-28 TEZZO）。SES（代表者）が登録する。代表者との違いは、担当者の登録・停止・退会ができないことだけ（2026-10-31 TEZZO） |
| EG（エンジニア） | 自分の情報とスキルシートを整え、案件に応募し、面談を受ける |
| 管理者の直属の EG | SES に属さず、管理者の下にいる EG |

- 上位から下位への登録は、管理者 → SES → EG で同じ形にそろえる（2026-10-30 TEZZO）。

## 4. 業務の流れ

**準備（最初に1回）**

1. 上位が下位を登録する（管理者 → SES、SES → EG）。下位に**仮登録メール**が届く。
2. 下位が**本登録**をする（必須項目は 5 章 R04）。
3. EG が自分の情報を登録する。やり取りしながら、理想のスキルシートを作る。

**案件ごと（届くたびに）**

4. 案件が届き、システムが条件に合う EG を選んで送る（SES にも知らせる）。
5. EG が案件に応募する。
6. 面談の依頼が入る。このとき、面談対策の Q&A を提案する。
7. 面談 → 合格（成約）。
8. 結果と落ちた理由をためて、次に活かす。

## 5. 機能要件

| 番号 | 要件 | 状態 |
|---|---|---|
| R01 | ログイン：パスワードと確認コード。確認コードを一度通った人には二度と求めない。兼任の人は、入るときに立場を選ぶ | 済 |
| R02 | 上位が下位を登録すると、下位に**仮登録メール**が届く（管理者 → SES、SES → EG で同じ形）。どんなメールが届くかがわかる | 未（今は登録した時点で参加中になり、招待メールが届く） |
| R03 | 状態：仮登録 → 本登録 → 参加中 → 停止・退会 | 一部（参加中・停止・退会はある。仮登録・本登録が無い） |
| R04 | SES の本登録の必須項目：代表者姓・代表者名・企業正式名称・住所・電話番号。担当者の姓名は担当者本人の本登録で取る。仮登録は会社名でよい | 未（EG：姓・名・ふりがな・電話・住所。管理者：姓・名・電話） |
| R05 | 管理者がメールアドレスを登録して招待を送る流れ | 一部（招待はある。流れを作り直す） |
| R06 | 一覧から 停止・再開・退会・詳細 ができる（自分自身と、最後の使える管理者は不可） | 済 |
| R07 | 案件を受け付け、仕分けて、条件に合う EG に送る（SES にも知らせる） | 一部 |
| R08 | EG が案件に応募し、応募・面談・成約を記録する | 一部 |
| R09 | 理想のスキルシート：EG とやり取りして、事実にもとづいて作る。案件ごとに合わせて出す | 一部 |
| R10 | 面談対策の Q&A：面談の依頼が入ったら、その案件に合わせて提案する | 一部 |
| R11 | 学習ループ：結果と落ちた理由をためて、次の応募・面談に活かす | 未 |
| R12 | 請求：成約時に初期費用、その後は月額（率は 7 章） | 一部 |

- 「一部」は、v0.1.0 のアプリを確かめて「済」か「未」に分ける（まだ確かめていない）。

## 6. 非機能要件

| 番号 | 要件 |
|---|---|
| N01 | 個人情報（スキルシートなど）は、本人の同意を取って扱う。事実を盛らない |
| N02 | 案件の内容や会社の名前を、外部のサービスに渡さない |
| N03 | 使用中の管理者のメールは画面から変えられない（乗っ取り防止） |
| N04 | 公平：TEZZO はシステムの運営に徹する。EG としても入るなら、公平のルールと誓約書を作る |
| N05 | 速さ・使いやすさ・バックアップの決まり（まだ書いていない） |

## 7. 制約・前提

- アプリ：PHP の Laravel 12 ＋ MySQL（htdocs の `park`）。公開版は https://www.jona.jp/park/（Xserver）。
- 収益（案）：基準は案件に書かれた金額（SES が SH から受け取る金額）。成約時に初期費用 7%、その後は契約が続く間 月額 3%（契約は3か月ごと、延長は SH が決める）。払うのは SES。先払いなし。率は阿部さんの意見を聞いて決める。
- 数字は保守的にする。仮の数字には「仮」と書く。
- このリポジトリは公開。書く内容は公開されても困らないものにする。
