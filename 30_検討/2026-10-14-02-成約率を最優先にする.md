## 1. 決まったこと

## 2. なぜ成約率が土台か

- こちらの収入 ＝ 成約件数 × 案件の金額 × 報酬率（初期7%＋月額3%×続いた月数）。
- ビジネスパートナーの得も、**GP で成約が約1.4倍以上に増えるか**で決まる（`2026-10-14-01-事業構想の整理.md`）。
- 「3か月の契約で、相性が悪いとすぐ切られる」ので、**成約後の延長率も、成約率の一部**として扱う。
- つまり、成約率が上がらなければ、tezzo・阿部さん・ビジネスパートナーの3者のバランスが、どれも成り立たない。

## 3. 流れ（ファネル）と、落ちる原因の仮説

案件の受信 → 仕分け → 応募（スキルシート提出）→ 書類通過 → 面談 → 成約 → 延長

| 段階 | 落ちる原因の仮説 |
|---|---|
| 仕分け・応募 | 要件に合わない案件に応募している／応募が遅く先に埋まる／同じエンジニアが複数のビジネスパートナー経由で二重に応募される |
| 書類 | スキルシートの見せ方が弱い（作業内容が曖昧、技術の羅列、成果が数字でない）／案件の要件に合わせていない |
| 面談 | 受け答えの準備不足／逆質問がない／条件（稼働・開始日・単価・リモート）のずれが面談で発覚する |
| 成約・延長 | 配属後の相性／困りごとが SH に伝わる前に切られる |

※ いずれも仮説。**実際にどこで落ちているかの数字は、まだ無い**（最初に取る）。

## 4. システムの全体図

```
入口：案件の取り込み・仕分け
  └ 案件票（要件を構造化）
中核：マッチングと応募の準備
  ├ 経験票（エンジニアの経歴を構造化）
  ├ 適合判断（応募する／しない）
  ├ スキルシートの案件別最適化
  └ 面談の準備（質疑応答集・模擬面談・逆質問）
出口：面談 → 成約 → 延長
  └ 面談後のフィードバック・成約後のフォロー
学習ループ：全段階の結果と「落ちた理由」を記録し、中核に戻す
```

## 5. アイディア一覧（優先順）

| 優先 | アイディア | 中身 |
|---|---|---|
| 1 | **A. 計測（ファネルの記録）** | 応募→書類→面談→成約→延長を、1件ずつ記録し、落ちた理由を1行で残す。最初は表計算で足りる。これが全ての土台（改善の前後を比べられる） |
| 2 | **B. 案件票** | 案件の要件を、必須／歓迎、環境、単価、期間、開始日、稼働、リモート、面談回数、に分けて構造化する。AI で、メール本文から抜き出す |
| 2 | **C. 経験票** | エンジニアの経歴を、プロジェクト単位（技術、役割、規模、成果、使った期間）で構造化する。**事実だけ**を入れる |
| 3 | **D. 適合判断** | 案件票と経験票を突き合わせて、応募する／しないを決める。「応募しない」判断も成約率を上げる（ミスマッチ応募が減り、SH の信頼も上がる）。最終判断は人 |
| 3 | **E. スキルシートの案件別最適化** | 案件のキーワードに合わせて、経験の順番・強調を組み替える。1ページ要約、成果は数字で。**盛らない**（事実と違う記載は、後でトラブルになる） |
| 3 | **F. 面談の準備** | 案件票から想定質問を作る（質疑応答集）、AI で模擬面談、逆質問の候補。tezzo の「面談で通る型」を入れる |
| 4 | **G. スピードと一本化** | 受信から応募までの時間を短くする。同じエンジニアの二重応募を GP で一本化する（SH から見ても印象が良く、**GP にしかできない価値**） |
| 4 | **H. 条件の事前確認** | 稼働日数・開始日・単価・リモート・面談日程を、応募の前に本人と確認する。面談で条件が合わずに落ちるのを防ぐ |
| 4 | **I. 面談後のフィードバック** | 面談後に、SH・ビジネスパートナー経由で、落ちた理由や印象を1行で聞き、A に記録する。次の応募・面談準備に反映する |
| 5 | **J. 成約後のフォロー** | 配属後の最初の1か月に、短いヒアリング（困りごと・相性）をする。延長率の改善と、早期の離脱の兆しの把握 |
| 5 | **K. 経験者によるレビュー** | tezzo（15年以上）や現場の経験者が、スキルシートと受け答えを見る。別途報酬（構想済み） |

## 8. 気をつける点

- スキルシートは個人情報。本人の同意を取り、AI に渡すときは氏名・会社名を伏せる（ひな形づくりに使う程度にとどめる）。
- 事実を盛らない。AI の文章は、本人が事実を確認してから出す。
- SH・案件の情報を、外部のサービスに渡さない。
- 取り扱う件数が少ないうちは、率が大きくぶれる。1件の結果で判断しない。
